## Summary

1. **Overall health is good on the axes AGENTS.md pins hardest** — stdlib-only holds, exceptions are typed, flag>env>default is honoured in `cli.py`, the manifest/sha256 idempotence is real, and the TOON codec is cleanly separated from Crucible's. The code is well-commented and CR-cited.
2. **But the one remaining target is not served:** measured against installed Pi 0.86.1, `_emit_pi` produces extensions that cannot load (no default factory), cannot deliver the payload (no `stdin` in `pi.exec`), and cannot fail closed (`exec` never rejects). Every Pi hook is currently a no-op, and the scaffold's `open` default plus `.gitignore`d `.pi/` compound it.
3. **Roughly 40% of `hooks.py`, plus the symlink stage in `deploy.py` and the `CLAUDE.md` emission in `scaffold.py`, serve dropped or never-verified harnesses** and — via `HARNESS_SKILL_DIRS` — still write under `~/.claude`. CR-025 §S5 fences this off deliberately; a dedicated roster-prune CR is needed.
4. **Two path-resolution rules diverge**: the installer records `tool_scripts_dir` but the scaffold looks for a `target_root` key that is never written, so sandboxed installs compile wiring pointing at the real home. Atomic writes exist only for `install.toml`; the "any failure writes nothing" claim in `scaffold.py` is false.
5. **Top 3 to fix first:** (1) `hooks.py:308-312 / :215-220 / :135` — make the Pi extension a real default-export factory that actually delivers the payload and honours `closed`, with a loader-level test; (2) `scaffold.py:433-435` ↔ `cli.py:238-245` — one `target_root` source of truth in `install.toml`; (3) file the roster-prune CR removing `claude-code`/`hermes`/`opencode` code paths and the `.claude/skills` symlink writer (then flip scaffold guards to `closed` and stop gitignoring `.pi/extensions/`).
