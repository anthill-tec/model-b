## Context

A stack's agents are pointed at reference material in `docs/memory/` templates: `rust.toml` cites the
`rust-orchestration` template, and the quarkus agents are pointed at the Java references (CR-MDB-086).
CR-MDB-060 retires `docs/memory/`. A Pi skill gives agent-facing material a home its readers load:
only its name and description reach the prompt, its `SKILL.md` is read when a task matches, and its
`references/` when `SKILL.md` points to them. A skill rendered into a project's `.agents/skills/`
reaches only that project's sessions, and a sub-agent's catalogue, built from its own directory,
includes it; a worktree child finds the tracked copy in its worktree. A definition already tells its
agent which skills to load: a role's `skills` list in the stack file renders as the body line "Load
these skills first: …".

This CR builds the mechanism and moves rust's and arduino's agent-facing material. The Java stack
skill's content is CR-MDB-086.

## §S1 — The mechanism

1. A stack skill's source is `generator/skills/<name>/`, its directory named as its frontmatter
   `name`: a `SKILL.md`, and a `references/` directory only when the skill has references.
   `generator/` ships in the wheel; the installer deploys nothing from it. The source resolves through
   the same asset-root chain as the agent sources (packaged first, then the repository).
2. Which stacks render which stack skill is declared once, beside the stack files; this CR declares
   `rust-stack` for the `rust` stack. A stack that declares none ships none; an empty skill is never
   rendered.
3. `modelb-axi init` renders the stack skill of each stack in `--stacks` that declares one into
   `.agents/skills/<name>/` at the project root, never in a sub-project, under the ownership rules of
   the rendered agent definitions:
   - `SKILL.md` carries Model B's generated marker inside its frontmatter;
   - each reference carries it as its first line, an HTML comment
     (`<!-- generated by modelb-axi (Model B stack skills); sha256 <hash> -->`), read by the first-line
     ownership form;
   - a hand-modified file is skipped and reported; an unmarked file is never written;
   - `--dry-run` writes nothing; the rendered files are tracked, so every worktree carries them.
4. `modelb-axi agents`, run from the project root as today, re-renders the stack skills with the agent
   definitions, by the same rules. A re-render writes and never deletes: a stack skill for a stack the
   project no longer lists stays where it is.
5. **The rendered `AGENTS.md`'s stack line** names a stack's skill only where it declares one, and
   names no stack skill for a stack without one. **Both trust surfaces** — the untrusted-project
   warning `init` prints and the rendered `AGENTS.md`'s project-trust line — name the stack skills
   among what an untrusted project does not load.

## §S2 — The definitions load it

Every role of the `rust` stack lists `rust-stack` in its `skills`, so each definition's body line
names it, e.g. "Load these skills first: crucible, rust-stack." `SKILL.md` restates nothing its stack
file states; references move verbatim, apart from the rewordings §S5 requires.

## §S3 — rust and arduino: every agent-facing section leaves its template

An agent-facing section of a template goes to the stack skill when only some tasks need it, into the
stack file when every phase needs it (only the part the stack file does not already state), or is
deleted from the template when the stack file already states all of it. Orchestrator-facing sections
stay for CR-MDB-060.

1. **`rust-orchestration.md`:**

   | Section or bullet | Goes to |
   |---|---|
   | "E2E / docker / nextest-concurrency gotchas", and the "Pre-merge gate" bullet that a new docker-dependent test joins both nextest default-filters | `rust-stack` `references/e2e-docker-nextest.md` |
   | "Flaky-test investigation principle" (the principle) | `rust-stack` `SKILL.md` |
   | "Flaky-test investigation principle": its "Gate sizing follow-on" paragraph | stays |
   | "RED/GREEN/VERIFY additions" | `rust.toml`, in the gotchas of the roles each bullet names, less what `rust.toml` states |
   | "Clippy runs with `--tests`" (in the additions) | `rust.toml`: the clippy commands in the RED, GREEN and VERIFY gotchas pass `--tests` |
   | "Test naming" | `rust.toml`, less what it states (CR-named tests) |
   | "RED that won't compile", "Crucible ingest routing" | deleted (already stated in `rust.toml`) |
   | Preamble, "Tooling", "Use the CLI", the `worktree-flow.py` subcommands, "Test scope", "Pre-merge gate" (other bullets), "Disk hygiene", "CARGO_BUILD_JOBS cap" | stays |

2. **`arduino-orchestration.md`:** the "Hardware drivers" rules join `arduino.toml`'s GREEN and FIX
   gotchas; "Test tiers and agents" stays; the preamble no longer names gating hardware drivers.
3. `rust.toml` cites no template path, its provenance header comment included. No `arduino-stack` skill
   is rendered.

## §S4 — Text that stays points at where material went

Every sentence left in a template that names a moved section names its new home.

## §S5 — The test-run rule reaches the skills

No stack skill teaches a runner invocation (§D21). A form the raw-runner guard's rules match that an
agent runs becomes the stack client's verb; a descriptive or checklist form is reworded or dropped. A
stack skill names no `ctx_*` or lean-ctx tool, because it is not rendered in a built-in form as the
definitions are.

## §S6 — The guards, the gates and the docs

1. **Gates whose roots gain `generator/skills/`:** the raw-runner guard, the AXI envelope guard, the
   skill-frontmatter checks and the Pi skill-loader check (no diagnostics, one skill per directory,
   name and description within Pi's limits, no name shared with a `skills-src/` bundle), and the
   shipped-text gates `test_tooling_detachment`, `test_deployed_script_invocation`,
   `test_project_registry_schema`, `test_worktree_flow_surfaces` and `test_board_holds_the_queue`.
2. **The orchestrator-rule triage stays frozen.** `archive/mapping.md` gains a row for each section
   §S3 moves (old `<template> § <section>` to its new place), and `test_orchestrator_rule_triage`
   resolves a destination that moved through those rows: to a skill file by its heading, or to a
   stack file as `` `generator/stacks/<stack>.toml` § gotchas.<role> ``, the destination text present
   under that key. Its classes' rules, the `duplicate` class's included, hold for the resolved place;
   `audits/2026-09-26-orchestrator-rule-triage.md` is not edited.
3. **Tests repointed** to the moved text: `test_orchestrator_rule_triage`'s check of the arduino
   template's "Hardware drivers" heading, and `test_rust_stack_generator`'s reads of
   `rust-orchestration.md`.
4. `AGENTS.md` § Key Directories names `generator/skills/`.

## Acceptance criteria

- [ ] **AC1 (§S1.1–3).** `generator/skills/` holds exactly `rust-stack/`, with a `SKILL.md` whose
      frontmatter `name` is `rust-stack` and `references/e2e-docker-nextest.md`. `init --stacks rust`
      (sandboxed) writes `.agents/skills/rust-stack/SKILL.md` with the marker in its frontmatter and the
      reference with the HTML-comment marker as its first line; `--stacks python`, `bun`, `arduino`,
      `quarkus` and `java` write no `.agents/skills/`; `--dry-run` writes nothing; a hand-modified
      rendered file is skipped and reported, and an unmarked file at a rendered path is left
      untouched, by both `init` and `modelb-axi agents`.
- [ ] **AC2 (§S1.2, §S1.4).** `modelb-axi agents` at a rust project's root re-renders `rust-stack`; a
      second run changes nothing; after the project drops rust it deletes nothing. A declared stack
      skill with an empty source renders nothing.
- [ ] **AC3 (§S1.5).** A rust project's rendered `AGENTS.md` stack line names `rust-stack`; a python,
      bun or arduino project's names no stack skill; the untrusted-project warning and the `AGENTS.md`
      project-trust line each name the stack skills.
- [ ] **AC4 (§S2).** Every rendered rust definition's skills line names `rust-stack`; no other stack's
      definition names a stack skill.

      skill-loader checks over it pass with no diagnostics.
- [ ] **AC9 (§S6.2–4).** `archive/mapping.md` carries a row for each §S3 move;
      `test_orchestrator_rule_triage` passes with the audit file unchanged; `AGENTS.md` names
