# Crucible Report — Bun / TypeScript

`clients/bun-crucible.py` is the CLI client — it runs the tests AND ingests to
the Crucible v2 API in one call under your agent id. Direct `curl`/`fetch`
against the v2 endpoints is the fallback for edge cases only.

> **MANDATORY for RED/GREEN/regression cycle runs:** run the tests **through
> the client** (`test` for a targeted cycle, `regression` for the gate). Do NOT
> invoke `bun test` directly for a cycle run and then hand-ingest.

## Workflow context (env convention)

The client stamps every ingest with a `tier` (`unit` for targeted runs,
`regression` for the gate) and forwards workflow context read from the
environment — set these on every call so runs land on the right cycle:

| Env var | Meaning |
|---------|---------|
| `WORKFLOW_CYCLE` | Cycle label string → `context.cycle` |
| `WORKFLOW_WAVE` | Optional wave number |
| `WORKFLOW_ROLE` | Optional role/track label |

## Bun / TypeScript

### Lifecycle

```bash
python3 clients/bun-crucible.py register --agent AGENT_ID --phase RED
# ... work ...
python3 clients/bun-crucible.py unregister --agent AGENT_ID
```

### Targeted Run (RED or GREEN — no coverage; tier: unit)

```bash
WORKFLOW_CYCLE="my cycle label" \
python3 clients/bun-crucible.py test --tests tests/my-feature.test.ts --agent AGENT_ID
```

Runs `bun test` with a JUnit reporter, parses the XML, and POSTs
`/api/v2/runs/parsed` (or `/api/v2/runs/compile` when the suite fails to load).

### Regression Run (full suite — with lcov coverage; tier: regression)

```bash
WORKFLOW_CYCLE="my cycle label" \
python3 clients/bun-crucible.py regression --coverage --agent AGENT_ID
```

Coverage is parsed from `coverage/lcov.info` and sent in the SAME
`/api/v2/runs/parsed` payload. The server discards coverage on failing runs.

### Type gate

```bash
python3 clients/bun-crucible.py check --agent AGENT_ID     # tsc → /api/v2/runs/compile
python3 clients/bun-crucible.py auto-ingest --agent AGENT_ID  # ingest an existing report
```

### Report Locations (Bun)

| Artifact | Path | Generated by |
|----------|------|-------------|
| JUnit XML | `/tmp/bun-junit.xml` (client-managed) | `bun test --reporter=junit` |
| lcov coverage | `coverage/lcov.info` | `bun test --coverage` |

## Event Management

All GETs support compact TOON responses (`?fmt=toon` or `Accept: text/toon`)
for cheap reads; JSON responses carry `help` hints.

```bash
# List events (default limit 50)
curl -s "http://localhost:3849/api/v2/events?limit=20&fmt=toon"

# For a specific project
curl -s "http://localhost:3849/api/v2/events?project=PROJECT_KEY_UUID&limit=20"

# Read / delete a single event
curl -s "http://localhost:3849/api/v2/events/EVENT_ID"
curl -s -X DELETE "http://localhost:3849/api/v2/events/EVENT_ID"
```

## API Endpoint Reference

| Endpoint | Method | Purpose |
|----------|--------|---------|
| `/api/v2/runs` | POST | Ingest raw test data (codec + data or dataPath) |
| `/api/v2/runs/parsed` | POST | Ingest pre-parsed results (summary + tree + optional coverage; accepts tier/stack/context) |
| `/api/v2/runs/compile` | POST | Ingest compile failure (errors string + format) |
| `/api/v2/agents/register` | POST | Register/touch agent (upsert; ingest is the heartbeat afterwards) |
| `/api/v2/agents/unregister` | POST | Unregister agent (requires agentId + projectKey) |
| `/api/v2/agents` | GET | List agents (optional ?project filter) |
| `/api/v2/events` | GET | List events (optional ?project, ?limit) |
| `/api/v2/projects` | GET/POST | List / create projects |

## Placeholders

Replace these in all commands:

| Placeholder | Meaning | Example |
|-------------|---------|---------|
| `PROJECT_KEY_UUID` | Crucible project key | `019c9ff7-222f-7ae5-9121-2ae549e4d97a` |
| `AGENT_ID` | Your agent ID from the prompt | `CR-CRU-008-RED` |

## Rules

- **Never skip ingest** — every test run (RED, GREEN, regression) gets reported
- **Ingest RED and GREEN separately** — Crucible must show the RED→GREEN transition
- **Compile/type failures get ingested too** — `/api/v2/runs/compile`
- **Coverage ONLY on full green regression** — targeted, partial, or failing runs produce misleading lcov; the server also discards coverage on failing runs as a safety net
- **Do NOT ingest coverage as a separate call** — `/api/v2/runs/parsed` takes `coverage` in the same payload
- **Always register before first ingest, unregister when done** — both require `agentId` + `projectKey`
- **`displayName` goes inside `identity` object** — top-level displayName is silently ignored
- **Read error responses and `help` hints** — they tell you exactly what's wrong and what to do next
